## 📖 项目背景与核心问题

官方的 **Behringer DCX-Remote 1.16a** 软件开发于十多年前。它的端口扫描机制非常死板；如果系统 COM 端口在软件初始化的瞬间没有处于“完全激活”或“准备好握手”的状态，软件将无法识别设备。

* **硬件特性：** DCX2496 机架处理器依赖 `DTR` (数据终端准备好) 和 `RTS` (请求发送) 信号进行 RS-232 通信。许多现代 USB 转 RS-232 适配器在空闲状态下不会输出这些信号。
* **系统环境：** 在像 Windows 10 LTSC IoT 这样精简的系统上，操作系统不会高频主动轮询 USB 设备。这通常会导致硬件在软件尝试扫描时仍处于“半睡眠”状态。

## 🛠️ 解决方案

为了确保 **100% 的连接成功率**，我们开发了这个预激活脚本。它充当一座桥梁，在启动软件之前先激活端口。

1. **强制唤醒：** 在主软件启动之前，脚本在系统底层强制打开选定的 COM 端口。
2. **信号补偿：** 它手动将 `DTR` 和 `RTS` 信号拉高，“激活” USB 转 RS-232 芯片，确保物理通信链路完全建立。
3. **自动移交：** 在硬件“唤醒”后的 800 毫秒内，脚本释放对串口的控制，并无缝拉起 `DCX-Remote.exe` 软件。

## ✨ 特性

* **🌐 双语支持：** 适配不同语言偏好的操作员 (英文/中文)。
* **🔍 动态识别：** 自动扫描当前系统的 COM 端口，无需手动检查 Windows 设备管理器。
* **⚙️ 高度灵活：** 支持自定义波特率 (默认使用 **38400**，这是 DCX 设备的最佳速率)。

## 🚀 最终效果与使用方法

使用此脚本后，用户不再需要：
- ❌ 反复插拔 USB 线缆以强制软件识别。
- ❌ 不断在设备管理器中核对端口号。
- ❌ 忍受软件启动后显示“Offline (离线)”状态的挫败感。

### 快速开始
1. 运行 `DCX_Run.exe` (或 `Script\Universal-COM-Starter.ps1`)。
2. 按照屏幕提示选择您的 COM 端口和波特率 (通常为 `38400`)。
3. 脚本将自动初始化端口并启动 Behringer `DCX-Remote.exe` 软件，准备就绪以进行连接。

## 🏗️ 编译启动器

如果您修改了 PowerShell 脚本 (`Universal-COM-Starter.ps1`) 并希望重新编译可执行启动器 (`DCX_Run.exe`)：

1. 确保在 PowerShell 中安装了 `ps2exe` 模块：
   ```powershell
   Install-Module ps2exe -Scope CurrentUser
   ```
2. 在根目录下运行 `build.cmd`。这将编译脚本，附加提供的图标，并生成新的 `DCX_Run.exe`。
